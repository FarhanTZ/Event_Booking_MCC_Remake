Product Requirement Document (PRD) — Module: Guest & Public UserSystem Name: Sistem Reservasi Gedung MCC (Malang Creative Center)Target Actors: Guest (Unauthenticated Visitor) & Public User (Authenticated Community/Creator/Institusi)Technology Stack: Laravel 11, PHP 8.4, PostgreSQL 17, Redis, Tailwind CSS, Alpine.jsDocument Status: Approved for Implementation1. System Vision & ObjectiveMenyediakan portal publik mandiri (self-service) yang transparan dan akuntabel bagi calon penyelenggara acara di gedung MCC. Modul ini bertujuan mengeliminasi birokrasi manual, mencegah perebutan jadwal secara bersamaan (zero double-booking), serta mengamankan hak pemakaian gedung melalui penguncian slot berbasis waktu dan pengumpulan identitas legal pemohon.2. Functional Specifications (FR)Module 1: Katalog & Kalender Publik (Guest & User)FR-USR-01 (Katalog Ruangan):Menampilkan grid kartu ruangan aktif (rooms.is_active = true).Filter interaktif: Lantai (floor_level: 1–8), rentang kapasitas (capacity), dan peruntukan layout (supported_layouts).Setiap kartu memuat thumbnail utama (room_images.is_primary), kapasitas, luas ruangan, dan badge fasilitas unggulan.FR-USR-02 (Halaman Detail Ruangan):Slider foto ruangan lengkap dengan caption visual.Daftar inventaris fasilitas bawaan (room_facilities: nama, jumlah, kondisi).Panel informasi operasional: buffer time 30 menit dan ketentuan tarif komersial/subsidi.FR-USR-03 (Kalender Ketersediaan Real-Time):Tampilan grid waktu per jam operasional gedung (08:00 – 22:00 WIB).Indikator warna slot:Hijau (Available): Kosong dan dapat dipesan.Kuning Berkedip (In-Progress/Locked): Sedang diisi pemohon lain via Redis lock.Merah (Booked): Sudah disetujui / aktif di tabel booking_slots (operational_range &&).Abu-abu (Buffer/Maintenance): Jeda 30 menit pasca-acara atau perawatan teknis.Module 2: Slot Locking & State Preservation EngineFR-USR-04 (Progressive Auth / Preserve State):Jika Guest mengklik slot kosong, sistem menyimpan parameter jadwal (room_id, date, start_time, end_time) ke session.Setelah login/register berhasil, pengguna langsung diarahkan ke form booking tanpa mengulang pemilihan slot.FR-USR-05 (Redis Slot Lock 15 Menit):Kunci dibuat dengan key pattern: lock:room:{room_id}:slot:{start_timestamp}_{end_timestamp}.Value: user_id pemesan; TTL: 900 detik (15 menit).Pengecekan overlap: Sistem memvalidasi bahwa rentang yang diminta tidak bertabrakan dengan data database (booking_slots.operational_range) dan tidak ada Redis key aktif pada rentang tersebut.Batasan: Maksimal 2 transaksi booking berstatus draft / active lock per akun.FR-USR-06 (Countdown Timer & Auto-Release):Alpine.js menampilkan countdown timer melayang (sticky top bar) di form pemesanan.Jika timer menyentuh 00:00:Kunci Redis dilepas otomatis.Tampilkan modal peringatan: "Sesi pengisian formulir berakhir. Slot Anda telah dilepas."Redirect kembali ke kalender ruangan.Module 3: Multi-Step Booking Wizard FormFormulir wajib dibagi menjadi 4 langkah dengan validasi ketat di setiap langkah:Step 1: Identitas Pemohon & Snapshot LegalitasAuto-fill dari tabel users: Nama Lengkap, Email, Nomor WhatsApp, Nama Lembaga/Komunitas, Tipe Lembaga.Bidang dapat disesuaikan: Kontak Darurat PIC Lapangan.Data ini disimpan sebagai snapshot ke event_details saat submit.Step 2: Detail Kegiatan & Kebutuhan Teknisevent_name (string, max 200 karakter, wajib).event_category (select: Seminar, Workshop, Pameran, Pertunjukan Seni, Rapat, dll.).estimated_participants (integer, wajib $\le$ rooms.capacity).event_description (text, minimal 50 karakter).Checklist fasilitas tambahan yang diajukan (requested_facilities).Step 3: Dokumen Legalitas & Komitmen Jaminan KTPUpload Berkas Proposal Kegiatan:Wajib berekstensi .pdf.Ukuran file: Min 100 KB, Maksimal 5 MB.Disimpan ke disk privat: private_documents/proposals/{uuid}.pdf.Checkbox Persetujuan Syarat Operasional:"Saya menyetujui bahwa penanggung jawab acara wajib menyerahkan FISIK KTP ASLI di meja Front Office saat check-in hari-H sebagai jaminan kepatuhan fasilitas." (Wajib dicentang, mencatat tos_agreed_at).Step 4: Ringkasan & Konfirmasi SubmisiMenampilkan kartu rekapitulasi data Step 1–3.Tombol "Kirim Pengajuan Permohonan":Menjalankan DB Transaction: Insert bookings, booking_slots, dan event_details.PostgreSQL Trigger trg_set_operational_range otomatis menghitung operational_range (jam acara + 30 menit buffer).Redis lock dihapus.Status transaksi menjadi awaiting_marketing.Module 4: Dashboard Pemohon, Revisi & E-PassFR-USR-07 (Dashboard Pemantauan Status):Daftar riwayat permohonan pengguna dengan badge status:Awaiting Marketing Review (Menunggu kurasi).Revised (Butuh perbaikan dokumen).Awaiting Payment (Khusus komersial, tombol chat WhatsApp aktif).Confirmed (Disetujui, E-Pass aktif).Rejected (Ditolak, menampilkan alasan resmi).FR-USR-08 (Alur Revisi Dokumen):Jika status revised, tampilkan catatan revisi dari tim Marketing dan countdown sisa waktu grace period 24 jam (bookings.revision_deadline).Form upload file proposal pengganti aktif.Saat user submit perbaikan: Status kembali ke awaiting_marketing.FR-USR-09 (E-Pass Digital & Validasi Hari-H):Khusus status confirmed, kartu tiket digital menampilkan:Kode Booking Unik (misal: MCC-2026-X89B).QR Code Dinamis (mengenkripsi checkin_token).Jadwal resmi acara (event_start_at s/d event_end_at).Peringatan registrasi: "Tunjukkan QR Code ini ke petugas Front Office lantai dasar dan titipkan KTP penanggung jawab acara."5. UI/UX & Interaction Design Rules (Tailwind & Alpine.js)Responsiveness: Optimal pada resolusi mobile ($375\text{px}$ – $430\text{px}$) hingga desktop ($1280\text{px}$ – $1920\text{px}$).Sticky Progress Indicator: Form wizard dilengkapi stepper [1] Identitas -> [2] Acara -> [3] Berkas -> [4] Selesai yang menampilkan status checklist.Optimistic UI Prevention: Tombol submit wajib memiliki state loading spinner dan disabled untuk mencegah double submit.Error Handling Visual:Validasi form menampilkan pesan error berwarna rose-600 tepat di bawah masing-masing input field.Gagal lock Redis menampilkan banner toast merah melayang: "Slot jam ini sedang diproses oleh pemohon lain. Silakan pilih slot lain."6. Acceptance Criteria (Definisi Selesai / DoD)[ ] Guest dapat menjelajah katalog, memfilter lantai/kapasitas, dan melihat kalender tanpa hambatan autentikasi.[ ] Memilih slot saat belum login berhasil diarahkan ke form login, dan setelah login langsung menuju formulir dengan data slot utuh.[ ] Redis berhasil mengunci slot selama tepat 15 menit; percobaan user kedua pada slot yang sama langsung digagalkan dengan respons informatif.[ ] Database PostgreSQL otomatis menolak (via exception) jika ada transaksi yang memaksa menyimpan rentang operational_range yang bertabrakan.[ ] Trigger PostgreSQL berhasil menambahkan 30 menit jeda operasional ke operational_range secara mandiri.[ ] File proposal tersimpan di direktori privat dan tidak dapat diakses secara publik lewat URL langsung.[ ] E-Pass hanya dapat diakses ketika transaksi telah mencapai status confirmed.
